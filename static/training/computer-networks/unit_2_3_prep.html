Topic 1: Framing and bit stuffing

The physical layer only sends a stream of 0s and 1s. It does not say where one message ends and the next begins. The Data Link Layer cuts the stream into small packets called frames. This lets the receiver find the start and end of each message, check each frame for errors, and ask for only the damaged frame again.

MethodHow it worksProblem with it
Character countThe first field of the frame says how many characters it containsIf the count is damaged, the receiver loses track of where the next frame starts
Flag bytes with byte stuffingEvery frame starts and ends with a FLAG byte. If the data contains FLAG, the sender puts an ESC byte before it. If the data contains ESC, it also gets an ESC before itWorks only with 8-bit characters
Flag bits with bit stuffingThe flag is 01111110. After every five consecutive 1s in the data, the sender adds a 0. The receiver removes any 0 that follows five 1sA few extra bits, but works for any kind of data

Why stuffing is needed: if the data contained 01111110 by chance, the receiver would think the frame had ended. Stuffing makes that pattern impossible inside the data.

Numerical 1.1

Problem: A sender uses bit stuffing with flag 01111110. The data to send is 01111101111110. Write the stuffed bit stream.

Given: Data = 01111101111110 (14 bits). Find: the stuffed stream. Rule: after every five consecutive 1s, insert one 0.

Solution:

  1. Read from the left: 0, then 11111 (five 1s). Insert a 0 straight after them.
  2. Continue with the original 0, then 11111 (five 1s again). Insert another 0.
  3. The remaining bits are 1 and 0. No more insertions.
Answer: 0111110011111010 (16 bits, 2 zeros inserted). Frame on the wire: 01111110 + 0111110011111010 + 01111110. The receiver removes the 0 after every five 1s and gets the original data back.

Numerical 1.2

Problem: Apply bit stuffing to 0110111110111111001.

Solution: Split it as 0110 + 11111 + 0 + 11111 + 1001. Insert a 0 after the first 11111. Insert another 0 after the second 11111. The sixth 1 after it starts a new count.

Answer: 011011111001111101001 (21 bits).

Numerical 1.3

Problem: Apply byte stuffing to the data sequence A, FLAG, B, ESC, C.

Solution: Put an ESC before FLAG and before ESC.

Answer: A ESC FLAG B ESC ESC C. On the wire: FLAG, A, ESC, FLAG, B, ESC, ESC, C, FLAG.

Try yourself: apply bit stuffing to 1111111111 (ten 1s). Answer: 111110111110. Use the tool to check your own bits.

Topic 2: Error detection using CRC

Noise on a link can flip bits. CRC (Cyclic Redundancy Check) lets the receiver notice this. The sender and receiver agree on a fixed bit pattern called the generator. The sender divides the data by the generator using a special division and attaches the remainder to the data. The receiver divides the whole frame by the same generator. A zero remainder means no error was detected.

Steps for the sender

  1. Let the generator have k bits. Its degree is k - 1.
  2. Add k - 1 zeros to the end of the data.
  3. Divide by the generator using modulo-2 division, where subtraction is XOR (same bits give 0, different bits give 1). No borrowing or carrying.
  4. The remainder has k - 1 bits. Replace the added zeros by the remainder. This is the transmitted frame.

CRC catches all single-bit errors and all burst errors no longer than the remainder length.

Numerical 2.1

Problem: The data is 1101011011 and the generator is 10011. Find the CRC remainder and the transmitted frame.

Given: Data = 1101011011, generator = 10011 (5 bits, degree 4). Find: remainder and transmitted frame.

Solution: The generator has 5 bits, so add 4 zeros: 11010110110000. Wherever the leftmost remaining bit is 1, XOR the generator with the next 5 bits. Where it is 0, skip ahead.

Start               11010110110000
XOR at position 0   (11010 XOR 10011 = 01001)  -> 01001110110000
XOR at position 1   (10011 XOR 10011 = 00000)  -> 00000010110000
XOR at position 6   (10110 XOR 10011 = 00101)  -> 00000000101000
XOR at position 8   (10100 XOR 10011 = 00111)  -> 00000000001110

The last 4 bits are the remainder: 1110.

Answer: Remainder = 1110. Transmitted frame = 1101011011 followed by 1110, which is 11010110111110.

Numerical 2.2

Problem: Data = 1010101, generator = 1011. Find the remainder and the frame.

Solution: The generator has 4 bits, so add 3 zeros: 1010101000.

Start               1010101000
XOR at position 0   (1010 XOR 1011 = 0001) -> 0001101000
XOR at position 3   (1101 XOR 1011 = 0110) -> 0000110000
XOR at position 4   (1100 XOR 1011 = 0111) -> 0000011100
XOR at position 5   (1110 XOR 1011 = 0101) -> 0000001010
XOR at position 6   (1010 XOR 1011 = 0001) -> 0000000001
Answer: Remainder = 001. Frame = 1010101001.

Numerical 2.3 (receiver check)

Problem: The receiver gets 1010101001 and uses generator 1011. Is the frame error-free?

Solution: Divide the received frame (without adding any zeros) by 1011. The remainder is 000.

Answer: The remainder is zero, so no error is detected.

Try yourself: data 1101, generator 1001. Answer: remainder 100, frame 1101100.

Topic 3: Sliding window protocols


Basic terms. A sequence number is written on each frame so the receiver can tell frames apart (n bits give 2n numbers). An ACK is a short message from the receiver meaning "I received it". A timeout happens when no ACK arrives in time, so the sender assumes the frame was lost. The window is how many frames the sender may send without waiting for an ACK.




Stop-and-WaitGo-Back-N (GBN)Selective Repeat (SR)

Here a = Tp / Tt. Tp is the propagation delay (time for a signal to cross the link) and Tt is the transmission time (time to push one frame onto the link). N is the window size.


Why GBN window is at most 2n - 1: if it were 2n and every ACK got lost, the receiver would see frame 0 again and could not tell whether it is a new frame 0 or a repeat of the old one.





Numerical 3.1


Problem: A Go-Back-N sender uses 3-bit sequence numbers. What is the largest sender window? The sender transmits frames 0 to 5 and frame 3 is lost. Which frames are retransmitted and why?


Given: n = 3, frames 0 to 5 sent, frame 3 lost. Formula: GBN window = 2n - 1.


Solution:


    

  1. Window = 23 - 1 = 7.
    2. 

  2. Frames 0, 1, 2 reach the receiver in order and are acknowledged.
    3. 

  3. Frame 3 is lost. Frames 4 and 5 arrive, but the receiver is still waiting for frame 3. A GBN receiver accepts only the next expected frame, so 4 and 5 are discarded.
    4. 

  4. The timer for frame 3 runs out. The sender goes back to 3 and sends 3, 4, 5 again.
    5. 



Answer: Maximum window = 7. Retransmitted frames = 3, 4 and 5, because the receiver discarded 4 and 5 and has no buffer for out-of-order frames.








Numerical 3.2


Problem: A GBN sender uses 4-bit sequence numbers and sends frames 0 to 7. Frame 5 is lost. Find the maximum window and the retransmitted frames.


Solution: Window = 24 - 1 = 15. Frames 0 to 4 are accepted. Frames 6 and 7 arrive out of order and are discarded.


Answer: Window = 15. Retransmitted: 5, 6, 7.







Numerical 3.3


Problem: In Selective Repeat with 3-bit sequence numbers, frames 0 to 5 are sent and frame 3 is lost. What is the sender window and which frames are retransmitted?


Solution: SR window = 2n-1 = 22 = 4. The receiver has a buffer, so it stores frames 4 and 5 until frame 3 arrives. Only frame 3 is sent again.


Answer: Window = 4. Retransmitted: only frame 3.







Numerical 3.4 (efficiency)


Problem: A link has a bandwidth of 1 Mbps. Each frame is 1000 bits. The one-way propagation delay is 20 ms. Find (a) the efficiency of Stop-and-Wait, (b) the efficiency of Go-Back-N with window 7, and (c) how many sequence-number bits GBN and SR need to reach 100% efficiency.


Given: Bandwidth = 1 Mbps = 1,000,000 bits/s. Frame = 1000 bits. Tp = 20 ms.


Formula: Tt = frame size / bandwidth. a = Tp / Tt. Stop-and-Wait efficiency = 1 / (1 + 2a). Window protocol efficiency = N / (1 + 2a), at most 1.


Solution:


    

  1. Tt = 1000 / 1,000,000 = 0.001 s = 1 ms.
    2. 

  2. a = 20 ms / 1 ms = 20.
    3. 

  3. (a) Stop-and-Wait = 1 / (1 + 40) = 1/41 = 2.44%.
    4. 

  4. (b) GBN, N = 7: 7/41 = 17.07%.
    5. 

  5. (c) For 100% we need N of at least 41. GBN: 2n - 1 ≥ 41, so 2n ≥ 42, smallest n is 6 (window 63). SR: 2n-1 ≥ 41, so 2n-1 ≥ 64, n - 1 = 6, n = 7.
    6. 



Answer: (a) 2.44%. (b) 17.07%. (c) GBN needs 6 bits and SR needs 7 bits.






Topic 4: ARP, RARP and GARP


Two kinds of addresses are involved. The IP address (like 10.0.0.7) says which network and host a device is on. The MAC address (like BB:BB:BB:BB:BB:BB) is burned into the network card. Inside a LAN, frames are delivered using MAC addresses, so a host that knows only an IP address must first find the matching MAC address.




ProtocolFull nameWhat it doesWhere it is used


ARPAddress Resolution ProtocolFinds the MAC address for a known IP addressEvery Ethernet or Wi-Fi LAN before sending a frame


RARPReverse ARPFinds the IP address for a known MAC addressOld diskless workstations at start-up. Replaced by BOOTP and DHCP


GARPGratuitous ARPA host announces its own IP-to-MAC mapping without being askedDetecting duplicate IPs, refreshing other hosts' caches after a card change, failover between backup routers




How ARP works


    

  1. Host A wants to send to IP 10.0.0.7 on the same LAN. It checks its ARP cache (a small table of known IP-to-MAC pairs). If the answer is there, it uses it.
    2. 

  2. If not, A broadcasts an ARP request to every host on the LAN: "Who has 10.0.0.7? Tell 10.0.0.5."
    3. 

  3. Every host receives it, but only the owner of 10.0.0.7 answers. It sends an ARP reply directly (unicast) to A with its MAC address.
    4. 

  4. A saves this pair in its cache and sends the data frame to that MAC address.
    5. 



If the destination is on a different network, A resolves the MAC address of its default router instead.






Numerical 4.1 (short answer style)


Problem: Explain how ARP lets a host in the Library send a frame to another host on the same LAN.


Answer: The Library host knows only the destination IP address. It looks in its ARP cache. If the MAC address is missing, it broadcasts an ARP request asking "Who has this IP?". Every host receives the request, but only the host with that IP replies, sending its MAC address directly to the requester. The sender stores the pair in its ARP cache and sends the data frame addressed to that MAC address.






Topic 5: ALOHA (Pure and Slotted)


Many stations share one channel (for example, many sensors on one radio channel). If two transmit at the same time, their signals collide and both frames are lost. ALOHA is a simple set of rules for sharing.


    

  • Pure ALOHA: a station sends whenever it has data. If no acknowledgement comes, it waits a random time and tries again.
    • 

  • Slotted ALOHA: time is divided into equal slots, each as long as one frame (T). A station may start sending only at the beginning of a slot.
    • 



The vulnerable period is the time window in which another station's transmission would collide with yours.

Here G is the average number of frame attempts (new plus repeats) per frame time, and S is the fraction of time the channel carries a successful frame. T is the time to send one frame.






Numerical 5.1


Problem: Many low-power sensors share one wireless channel using ALOHA. The channel has a transmission rate of 1 Mbps and every frame is 1000 bits long. Calculate the maximum throughput (in frames per second) of the channel with Pure ALOHA and with Slotted ALOHA.


Given: Bandwidth = 1 Mbps = 1,000,000 bits per second. Frame size = 1000 bits.


Find: Maximum throughput for Pure and Slotted ALOHA in frames per second.


Formula: Frame time T = frame size / bandwidth. Channel capacity = 1 / T frames per second. Maximum throughput = (maximum efficiency) × capacity.


Solution:


    

  1. T = 1000 / 1,000,000 = 0.001 s = 1 ms.
    2. 

  2. The channel could carry at most 1 / 0.001 = 1000 frames per second if it were never idle and never had a collision.
    3. 

  3. Pure ALOHA's best efficiency is 18.4%, so maximum throughput = 0.184 × 1000 = 184 frames per second.
    4. 

  4. Slotted ALOHA's best efficiency is 36.8%, so maximum throughput = 0.368 × 1000 = 368 frames per second.
    5. 



Answer: Pure ALOHA = 184 frames per second. Slotted ALOHA = 368 frames per second. Slotted ALOHA gives double the throughput.







Numerical 5.2


Problem: The same channel (1 Mbps, 1000-bit frames) has all stations together generating 250 frames per second, counting new frames and retransmissions. Find the throughput of Pure and Slotted ALOHA.


Given: T = 1 ms. Attempts = 250 frames per second.


Formula: G = attempts per second × T. Pure: S = G · e-2G. Slotted: S = G · e-G. Successful frames per second = S / T.


Solution:


    

  1. G = 250 × 0.001 = 0.25.
    2. 

  2. Pure: S = 0.25 × e-0.5 = 0.25 × 0.6065 = 0.1516. Frames per second = 0.1516 / 0.001 = 151.6.
    3. 

  3. Slotted: S = 0.25 × e-0.25 = 0.25 × 0.7788 = 0.1947. Frames per second = 194.7.
    4. 



Answer: Pure ALOHA is about 151.6 frames per second. Slotted ALOHA is about 194.7 frames per second.




Try yourself: a channel has a rate of 2 Mbps and 1000-bit frames. Find the maximum throughput of Pure and Slotted ALOHA. Answer: T = 0.5 ms, capacity = 2000 frames per second, Pure about 368 and Slotted about 736 frames per second.

Topic 6: Ethernet CSMA/CD and Binary Exponential Back-off


CSMA/CD (Carrier Sense Multiple Access with Collision Detection) is the rule set used on classic wired Ethernet, such as 20 computers on one shared segment.


    

  1. Listen first. A station checks whether the cable is busy. If it is, it waits.
    2. 

  2. Send. If the cable is free, it starts sending.
    3. 

  3. Keep listening while sending. If it detects another signal (a collision), it stops at once and sends a short jam signal so everybody knows.
    4. 

  4. Wait a random time, then retry. The waiting time comes from Binary Exponential Back-off.
    5. 



Binary Exponential Back-off (BEB). After the i-th collision, the station picks a random number K from 0 to 2i - 1 and waits K slot times before trying again. One slot time is 51.2 µs on 10 Mbps Ethernet. Each extra collision doubles the range, so repeated collisions between the same stations quickly become unlikely. The range stops growing at 1024 numbers (0 to 1023) after the 10th collision, and the frame is dropped after 16 failed attempts.

Numerical 6.1


Problem: A station on a CSMA/CD Ethernet has just had its 3rd collision. From how many slots does it choose its waiting time?


Formula: Choices after the i-th collision = 2i. Solution: 23 = 8, so K is chosen from 0, 1, 2, 3, 4, 5, 6, 7.


Answer: 8 slots.







Numerical 6.2


Problem: Two stations have just had their 3rd collision. What is the probability that they collide again on the next attempt? What is the longest a station may wait? Take the slot time as 51.2 µs.


Solution:


    

  1. Both stations choose from 8 slots (0 to 7). There are 8 × 8 = 64 equally likely pairs, and 8 of them have both stations choosing the same slot.
    2. 

  2. Probability of a collision = 8/64 = 1/8 = 12.5%.
    3. 

  3. Longest wait = 7 slots × 51.2 µs = 358.4 µs.
    4. 



Answer: Probability = 1/8. Longest wait = 358.4 µs.







Numerical 6.3 (minimum frame size)


Problem: A 10 Mbps Ethernet cable is 1 km long and signals travel at 200 m per microsecond. Find the minimum frame size so that a sender still hears a collision before it finishes sending.


Given: Length = 1000 m. Speed = 200 m/µs. Bandwidth = 10 Mbps.


Formula: The frame must last at least as long as the round-trip time. Minimum frame size = bandwidth × round-trip time.


Solution:


    

  1. One-way propagation time = 1000 / 200 = 5 µs.
    2. 

  2. Round-trip time = 2 × 5 = 10 µs.
    3. 

  3. Minimum frame size = 10,000,000 bits per second × 10 × 10-6 s = 100 bits.
    4. 



Answer: 100 bits.






Topic 7: Basic Bit Map protocol


Bit Map is a collision-free protocol. Stations take turns, so there are no collisions.


    

  1. Time is split into rounds. Each round begins with a contention period of N slots, one slot per station, where N is the number of stations.
    2. 

  2. In its own slot, station j puts a 1 if it has a frame to send, or stays silent (0) if not. Everybody hears all the bits.
    3. 

  3. After the contention period, the stations with a 1 transmit their frames in order of station number, lowest first.
    4. 



Efficiency. Let d be the frame length in bit times. At low load, efficiency = d / (d + N), because the whole contention period is overhead for a single frame. At high load (every station has a frame), efficiency = d / (d + 1), because the N-bit contention period is shared among N frames, so each frame carries about 1 bit of overhead.





Numerical 7.1


Problem: 8 stations numbered 0 to 7 use the Basic Bit Map protocol. Stations 1, 4 and 6 have frames to send. Show the contention period bits and the order of transmission.


Solution: There are 8 contention slots, one per station. Stations 1, 4 and 6 put 1 in their own slots. All other slots stay 0. After the contention period, the stations transmit in increasing station number.


Answer: Contention bits = 01001010. Order of transmission = station 1, then station 4, then station 6.








Numerical 7.2


Problem: 10 stations numbered 0 to 9 use Basic Bit Map. Stations 2, 5 and 9 are ready. Write the contention bits and the transmission order.


Answer: Bits = 0010010001. Order = 2, 5, 9.







Numerical 7.3 (efficiency)


Problem: A Bit Map network has N = 8 stations and each frame is d = 16 bit times long. Find the efficiency at low load and at high load.


Formula: Low load = d / (d + N). High load = d / (d + 1).


Solution: Low load = 16 / (16 + 8) = 16/24 = 0.667. High load = 16 / (16 + 1) = 16/17 = 0.941.


Answer: Low load = 66.7%. High load = 94.1%.




Try yourself: 8 stations (0 to 7), stations 0, 3 and 7 are ready. Answer: bits 10010001, order 0, 3, 7.




Topic 8: Adaptive Tree Walk and limited-contention protocols


    

  • Contention (ALOHA, CSMA): stations just try. Quick at low load, but collisions pile up at high load.
    • 

  • Collision-free (Bit Map, Token passing): stations take turns. No collisions, but the reservation overhead wastes time when few stations have data.
    • 

  • Limited contention (Adaptive Tree Walk): behaves like contention when load is light and like collision-free when load is heavy. It gets the good side of both.
    • 



Adaptive Tree Walk. Imagine the stations as the leaves of a binary tree.


    

  1. In slot 0, every station may transmit. If exactly one does, it succeeds. If none do, the slot is idle.
    2. 

  2. If two or more transmit, there is a collision. In slot 1 only the stations under the left child node may transmit.
    3. 

  3. If that slot collides again, go one level deeper to the left. If it succeeds or is idle, move to the right sibling next.
    4. 

  4. Keep going down the tree until every group has been resolved.
    5. 



Why limited contention is preferred. Pure contention wastes the channel in collisions when many stations are active. Pure collision-free methods waste time on reservation when few stations are active. Limited contention keeps the contention group small when the load is high, so collisions are few, and lets many stations try at once when the load is low, so delay is short.

Numerical 9.1 (short answer style)


Problem: Name the IEEE 802 standard for a laboratory Ethernet and for hostel Wi-Fi, and state one difference in how they handle collisions.


Answer: The lab Ethernet uses IEEE 802.3 and the hostel Wi-Fi uses IEEE 802.11. Ethernet detects a collision while it is transmitting and then stops and retries (CSMA/CD). Wi-Fi cannot detect collisions while transmitting, so it tries to avoid them with random back-off and acknowledgements (CSMA/CA).
