ARP — Address Resolution Protocol

Study notes with interactive diagrams. How a device turns an IP address into the MAC address it needs to actually put a frame on the wire.

1. Why ARP has to exist

Two different addressing systems meet inside every packet you send. Software thinks in IP addresses (Layer 3) — logical, assignable, and structured so routers can tell which network a host belongs to. But the frame that physically crosses an Ethernet segment is delivered using a MAC address (Layer 2), a flat hardware identifier baked into the network card.

A host that only knows "I need to reach 192.168.1.50" therefore cannot yet build a frame: the destination MAC field is empty. ARP is the lookup service that fills it in, by asking the local network directly.

Sequence: (1) no mapping known → (2) broadcast request to FF:FF:FF:FF:FF:FF → (3) switch floods the segment → (4) non-matching hosts discard, the owner recognises its IP → (5–6) owner answers with a unicast reply → (7) sender caches the mapping → (8) real data is sent.

The two asymmetries worth memorising

The question is a broadcast (destination MAC FF:FF:FF:FF:FF:FF) because nobody knows yet who should answer. The answer is a unicast, because the request already carried the asker's own IP and MAC — the replier knows exactly where to send it.

ARP cache

Broadcasting for every packet would be ruinous, so each host keeps a table of recently learned mappings. Dynamic entries age out after a few minutes so stale information cannot linger when a host changes address or NIC; static entries can be added by hand and never expire.

3. When the destination is on another network

This is the part that trips people up. ARP is strictly local — broadcasts do not cross routers. If the target IP is outside the sender's own subnet, the host never ARPs for it. It consults its routing table, decides the traffic must go to the default gateway, and ARPs for the gateway. The frame is then addressed to the router's MAC while the IP header still names the final destination. Each router repeats this for the next hop.

Rule of thumb

Layer 2 addresses are rewritten at every hop. Layer 3 addresses stay the same from end to end. ARP only ever resolves an address that lives on your own local segment.

4. What is actually inside an ARP packet

ARP rides directly on Ethernet (EtherType 0x0806) — there is no IP header involved, which is why ARP cannot be routed. On an Ethernet/IPv4 network the fields are:

Hardware type1 = Ethernet
Protocol type0x0800 = IPv4
HW addr len6 bytes
Proto addr len4 bytes
Operation1 = request  |  2 = reply
Sender hardware addressasker's MAC
Sender protocol addressasker's IP
Target hardware addressall zeros in a request — the unknown
Target protocol addressthe IP being resolved

Note that the request already contains the sender's own MAC and IP. That is a free gift: every host that hears the broadcast can also refresh its cache entry for the sender, not just the one that answers.

5. Variants and the security problem

Gratuitous ARP

An unsolicited announcement about your own mapping, sent to nobody in particular. Used to detect duplicate IP addresses on a segment and, after a failover, to tell every neighbour to update its cache for an address that has moved to new hardware.

Proxy ARP

A router answers on behalf of a host that lives on another segment, lending out its own MAC. The asking host believes the destination is local. It can glue segments together transparently, but it blurs network boundaries and is usually best avoided.

ARP spoofing / cache poisoning

ARP has no authentication whatsoever: any host can claim any IP, and replies are accepted even when nothing was asked. An attacker forges replies so that victims cache the attacker's MAC for the gateway's IP, and traffic flows through the attacker's machine. Mitigations are switch-side — dynamic ARP inspection, DHCP snooping bindings, port security — plus encryption so intercepted traffic is useless.

IPv6 does it differently

IPv6 removes ARP entirely. Neighbor Discovery uses ICMPv6 Neighbor Solicitation and Neighbor Advertisement messages sent to a solicited-node multicast group, so only a small set of hosts is bothered instead of the entire segment.
